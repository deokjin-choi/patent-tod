## 4. 기능전개

### 4.1 목적과 가설

LLM으로 기능을 분해하는 것 자체는 새롭지 않다. Haddad와 Seibel(2025)은 GPT-4o에 몬테카를로 트리 탐색을 붙여 기능 구조를 만들고 공학 대학원생의 결과와 비교했다. Cai 등(2025)은 수상작 제품 설계 문서에서 기능 어휘 1,730개를 뽑아 기능 기반으로 삼고, LLM이 상위 기능을 반복해서 하위 기능으로 나누게 했다. 두 연구 모두 LLM이 받는 지식은 한 종류다. 앞의 연구는 모형 내부 지식에, 뒤의 연구는 제품 설계 문서라는 한 유형에 기댄다.

이 연구가 보이려는 것은 LLM 분해가 아니라, LLM에게 주는 지식의 구성이다. 가설은 다음과 같다.

> **가설.** 서로 다른 지식 유형을 체계적으로 결합하여 기능공간을 구축하면, 단일 유형의 지식에 의존하는 방법보다 기존 기술에서 충분히 다뤄지지 않는 기능적 요구를 더 잘 식별할 수 있다.

근거가 되는 생각은 이렇다. 지식 유형마다 기능을 바라보는 자리가 다르다. 공학 교재는 기계가 수행하는 기능을 중심으로 적고, 정책·수요 문서는 사용자가 처한 조건과 사람이 계속 맡는 일을 적는다. 한 유형만 쓰면 그 유형이 보지 않는 기능은 기능공간에 들어오지 않고, 따라서 특허와 비교할 기회도 없다.

역할은 나눈다. 기능의 추출과 전개, 유형 사이의 통합 초안은 LLM이 한다. 사람은 결과가 MECE한지(겹치지 않고 빠짐없는지), 특정 기술에 치우치지 않았는지, 추상화 수준이 맞는지를 판단하고 그 결정을 기록한다.

### 4.2 지식 유형

기능공간을 만드는 데 쓰는 지식은 다섯 유형으로 나눈다. 특허는 넣지 않는다. 특허는 기능공간과 비교해 대응을 세는 대상이므로, 기능공간을 만드는 데 쓰면 판정이 순환한다.

| 유형 | 담는 지식 | 기능공간에 더하는 것 |
|---|---|---|
| 1. 국제기구 지침·보고서 (FAO 등) | 수요가 생기는 이유, 사용자의 조건, 사람과 기계의 분업 현황 | 상위 요구 기능, 사람이 계속 맡는 기능, 제약조건과 이어지는 기능 |
| 2. 공학 교재·핸드북 | 해당 작업의 기능 과정과 작동 원리를 정리한 체계 지식 | 기능 분류의 기본 틀 |
| 3. 리뷰 논문 | 최근 기술 경로, 반복해서 지적되는 미해결 과제 | 최근에 생긴 하위 기능, 기술이 막히는 지점 |
| 4. 개별 연구 논문 | 특정 장치의 상세한 기능 흐름과 설계 사례 | 세부 하위 기능, 지원 기능 |
| 5. 표준·통제 어휘 (ISO, ASABE, AGROVOC 등) | 공식 용어 정의, 성능·안전 항목 | 용어 통일, 성능 기준과 이어지는 기능 |

### 4.3 절차

1. **자료 취합.** 유형별로 자료를 모으고, 기능 서술이 있는 문장을 발췌한다. 발췌마다 자료 번호, 지식 유형, 쪽·절 위치를 붙인다.
2. **유형별 전개.** LLM에게 상위 기능과 한 유형의 발췌만 주고 하위 기능을 전개하게 한다. 하위 기능마다 동사–목적어 형식, 물질·에너지·신호 흐름, 수행 가능한 주체(기계, 사람)와 근거 발췌 번호를 함께 내게 한다. 근거 발췌가 없는 기능은 따로 표시한다.
3. **통합.** 유형별 결과를 하나의 기능공간으로 합친다. 이름은 다르지만 같은 기능은 하나로 묶고, 서로 맞지 않는 전개는 대체 경로로 남긴다. 묶음 초안은 LLM이 내고 사람이 확정한다. 합친 기능마다 어떤 지식 유형이 그 기능을 뒷받침하는지 기록한다.
4. **사람 검토.** MECE, 기술 중립성, 추상화 수준을 판단한다. 기능을 지우거나 합치거나 나눈 결정과 이유를 기록한다.
5. **특허 대응.** 확정된 기능공간에 특허를 대응시킨다. 방법은 [extended-abstract.md](extended-abstract.md) 4.2절과 같다.

3단계의 출처 기록이 가설 검증의 근거가 된다. 어떤 기능이 한 유형에서만 나왔는지, 여러 유형이 함께 뒷받침하는지를 기능마다 알 수 있다.

### 4.4 가설 검증 설계

같은 상위 기능에 대해 기능공간을 여러 조건으로 만들고 비교한다.

| 조건 | LLM에게 주는 지식 |
|---|---|
| LLM 단독 | 자료 없이 상위 기능만. 선행연구에 가까운 기준선 |
| 단일 유형 | 4.2절의 한 유형만. 유형마다 하나씩 |
| 통합 | 다섯 유형 전부. 4.3절 절차 |

비교할 값은 세 가지다.

- **유효 기능 수.** 사람 검토를 거친 뒤 남은 하위 기능 수다.
- **저대응 기능 수.** 대응하는 특허가 적은 기능의 수다. 기능이 많으면 저대응 기능도 따라 많아지므로, 유효 기능 중 비율로도 본다. 저대응의 기준은 기능별 특허 수의 분포에서 정한다.
- **수요 근거가 있는 저대응 기능 수.** 저대응 기능 가운데 1번 유형(국제기구 지침·보고서)의 발췌로 수요가 뒷받침되는 기능의 수다. 가설이 맞으면 통합 조건에서 이 값이 가장 크다.

통합 조건에서 저대응 기능이 어느 유형에서 왔는지도 따로 센다. 저대응 기능이 특정 유형에서만 나온다면, 그 유형이 단일 유형 방법에서 빠지는 기능을 채운다는 뜻이다.

### 4.5 사례 적용: 과일·채소를 기계적으로 수확한다

상위 기능은 [extended-abstract.md](extended-abstract.md) 4.1절의 F0다. 현재의 F1–F4(수확 대상 식별, 수확 위치 조정, 작물 분리·채취, 수확물 수집·이송)는 FAO 문장과 공학설계 문헌을 보고 사람이 전개한 것이다. 이 결과는 4.4절의 조건과 비교할 사람 전개 기준으로 둔다.

유형별 자료 현황은 다음과 같다.

| 유형 | 자료 | 현황 |
|---|---|---|
| 1. 국제기구 지침·보고서 | FAO(2022) *The State of Food and Agriculture 2022*, FAO(2024) 기후스마트 기술 매핑 요약, FAO(2025) 디지털 농업·AI 로드맵 | 발췌 완료. 확장초록 3절 표 |
| 2. 공학 교재·핸드북 | Srivastava 등(2006) ASABE 교재 13장, Ruiz-Altisent·Ortiz-Canavate(1999) CIGR 핸드북 1.6.13–1.6.18 | 목차만 확인. [harvest-functional-processes.md](../../06_references/food-agriculture/harvest-functional-processes.md) |
| 3. 리뷰 논문 | 과일·채소 수확 로봇과 기계화 리뷰 | 수집 전 |
| 4. 개별 연구 논문 | 수확 장치 설계 논문 | 수집 전 |
| 5. 표준·통제 어휘 | ISO 6689:2021(콤바인과 기능 부품 용어), ASABE S515(채소 수확기의 팔레트 적재 이송), ASABE S664(생식용 특수작물 기계의 위생 설계), AGROVOC의 'tree shakers'(상위 개념 'harvesters') | 1차 검색. 본문 미확인 |

표준 쪽에서 1차 검색으로 확인한 것은 다음과 같다. 수확기의 기능 용어를 정한 ISO 표준은 콤바인, 즉 곡물용(ISO 6689:2021)이고, 과일·채소 수확기의 기능 용어를 정한 ISO·ASABE 표준은 찾지 못했다. ASABE에서 과일·채소 수확과 닿는 표준은 이송(S515)과 위생 설계(S664)처럼 수확 앞뒤의 작업을 다룬다. 이는 확장초록 3절의 FAO 문장, 곧 과일·채소 생산은 거의 기계화되지 않았다는 서술과 방향이 같다. 표준이 비어 있는 만큼 5번 유형은 FAO의 통제 어휘인 AGROVOC으로 보완한다.

통합 단계에서 다룰 문제의 예는 이미 보인다. 2번 유형의 ASABE 교재 목차는 기능 과정을 Removal, Control, Selection, Transportation으로 나눈다. 이름으로는 Selection–F1, Removal–F3, Transportation–F4가 닿지만, Control이 F2(수확 위치 조정)에 해당하는지 별도의 기능인지는 본문을 읽어야 정할 수 있다. 이런 판단이 4.3절 3단계의 통합과 4단계의 사람 검토에서 기록할 내용이다.

다음 할 일은 순서대로 다음과 같다.

1. 2번 유형 두 자료의 본문에서 기능 서술을 발췌한다.
2. 3·4번 유형의 자료를 수집한다.
3. 5번 유형의 표준과 AGROVOC 개념의 정의를 확인한다.
4. 유형별 전개와 통합을 실행하고, 결과를 사람 전개 기준(F1–F4)과 비교한다.

## 5. 저개발 기능 조합 탐색

4절은 기능공간을 만들고 특허를 대응시키는 절차다. 이 절은 그 대응 결과에서 기술개발이 덜 된 기능 조합을 찾는 절차다.

### 5.1 탐색 공간

분석 단위는 핵심 하위 기능을 직접 수행하는 장치 특허다. 핵심 하위 기능은 그것이 없으면 상위 기능이 성립하지 않는 하위 기능이다. 장치 특허마다 세 축의 값을 갖는다.

- **분업 방식.** 하위 기능 가운데 기계가 맡는 것의 조합이다. 사람 힘으로 쓰는 도구처럼 기계가 맡는 기능이 없는 경우도 하나의 분업 방식으로 센다.
- **대상.** 기술이 다루는 대상의 종류다.
- **작동 원리.** 핵심 하위 기능을 수행하는 물리적 원리다.

대상 × 작동 원리 × 분업 방식의 한 칸이 하나의 기능 조합이다. 세 축의 값은 특허 대응(4.3절 5단계)에서 얻는다. 대상은 LLM이 붙인 분류보다 특허 원문에 나온 대상 이름을 코드로 묶어 쓰고, 특허 분류와 대조한다.

### 5.2 가능한 칸 판정

빈 칸이 모두 공백은 아니다. 물리적으로 맞지 않는 대상과 작동 원리의 쌍은 원래 비어 있다. 그래서 대상 × 작동 원리 쌍마다, 분업 방식과 상관없이 특허가 일정 수 이상 있으면 가능한 쌍으로 본다. 저개발은 가능한 쌍 안에서만 판정한다.

### 5.3 저개발 측정

세 가지로 잰다.

1. **공백.** 가능한 쌍 안에서 특허가 없는 분업 방식이다.
2. **상대적 저개발.** 대상마다 특허 총량이 다르므로 건수만으로는 비교할 수 없다. 대상과 분업 방식이 서로 무관하다고 볼 때의 기대 건수를 구하고, 실제 건수가 그보다 크게 적은 칸을 찾는다. 비교 값은 관측 건수를 기대 건수로 나눈 비율이다.
3. **시간 추세.** 우선일 기준으로, 예전에는 출원이 있었으나 최근에 끊긴 칸과 처음부터 없던 칸을 나눈다.

### 5.4 사다리 공백

분업 방식은 기계가 맡는 하위 기능이 하나씩 늘어나는 사다리로 볼 수 있다. 한 대상에서 아래 단과 위 단은 차 있는데 사이 단이 비어 있으면, 그 사이 단을 우선 후보로 본다. 사이 단은 부분 기계화여서 값이 싸고 사람의 일을 일부만 대신하므로, 자원이 적은 사용자에게 맞을 가능성이 크다.

### 5.5 채울 수 있는 공백과 개발이 필요한 공백

부품 기술은 장치에 더해져 기계가 맡는 하위 기능을 늘린다. 그래서 공백 칸마다, 빠진 하위 기능을 수행하는 부품 기술이 같은 대상이나 같은 작동 원리에 이미 있는지 본다.

- 있으면 기존 특허의 조합으로 채울 수 있는 공백이다. 3.3절 후보 생성의 입력이 된다.
- 없으면 부품부터 개발해야 하는 공백이다.

### 5.6 사용 조건 적용

수요 문서가 말하는 사용자의 제약조건(동력원, 장치 형태, 필요한 기반시설 등)을 만족하는 칸만 남긴다. 그 안에서 남은 공백이 UIO 후보다.

### 5.7 판정 오류에 대한 방어

특허 대응은 LLM 판정이어서 틀린 칸이 있다. 0건과 2건의 차이는 판정 오류일 수 있으므로 세 가지 장치를 둔다.

- **이웃 조건.** 같은 대상의 다른 분업 방식, 같은 분업 방식의 다른 대상에 특허가 충분할 때만 공백으로 인정한다. 이웃까지 모두 비어 있으면 공백이 아니라 자료가 부족한 것이다.
- **민감도.** 신뢰도가 높은 판정만 쓸 때와 대상을 특허 분류로 나눌 때에도 공백이 남는지 확인한다.
- **수작업 확인.** 남은 후보마다 이웃 칸의 특허를 몇 건씩 직접 읽어 확인한다.

### 5.8 사례 적용: 과일·채소를 기계적으로 수확한다

- **핵심 하위 기능과 장치.** 핵심 하위 기능은 F3(작물 분리·채취)이고, F3를 직접 수행하는 특허가 수확 장치다. 분업 방식은 F1–F4 가운데 기계가 맡는 것의 조합이다. 사람 힘으로 쓰는 장대 도구는 F3를 직접 수행하지만 기계가 맡는 기능이 없다.
- **대상.** 작물이다. 카드의 대상 작물 이름(딸기, 토마토, 체리 등)을 코드로 작물군에 묶는다. LLM이 직접 붙인 작물군은 파일럿 8건 중 3건이 틀려 쓰지 않는다. CPC 그룹(따기·털기, 서 있는 채소, 뿌리작물 캐기, 낙과 줍기)과 대조한다.
- **작동 원리.** F3의 분리 원리(절단, 비틀기, 당김, 진동, 흡입, 캐기, 훑기)다. 토마토 수확 로봇(열매채소·절단)과 감귤 진동 수확기(나무 과일·진동)는 분업 방식이 같더라도 다른 칸에 들어간다.
- **사다리.** 사람 힘 도구(기계가 맡는 기능 없음), 동력 절단 도구(기계가 F3), 위치 인식이나 수집을 더한 장치(기계가 F1·F3 또는 F3·F4), 수확 로봇(기계가 F1–F4) 순이다.
- **사용 조건.** 소농 조건은 동력원(사람 힘, 배터리)과 장치 형태(손 도구, 밀거나 끄는 장치)로 건다. 장치 형태 판정은 파일럿에서 8건 중 4건이 틀려서, 동력원을 주로 쓰고 후보마다 확인한다.
- **코드.** 분포 집계는 `04_src/fv_harvest_mapping/70_aggregate.py`가 한다. 작물 사전, 가능한 쌍 판정, 관측/기대 비율, 사다리 공백, 부품 존재 판정은 전체 특허 대응이 끝난 뒤 붙인다.
