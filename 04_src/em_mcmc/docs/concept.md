# 이 골격이 하는 일 (개념)

준 글을 코드로 옮기면 통계 객체는 네 개다.

```
관측  X   특허의 키워드 카운트 벡터          (있음)
잠재  Z   그 특허가 앉는 시나리오 셀         (없음 → EM)
혼합  Q   그 특허의 기술 원천 비중           (없음 → MCMC 혼합)
제약  C   수준 쌍이 금지인지                 (불확실 → MCMC 제약)
공간  S   C를 통과한 셀의 집합
지표     S와 점유로부터 Coverage 등
```

축은 토픽 모델이 찾아내지 않는다. 글의 Edge AI 예시 세 개를 **사전에 잠근다**.

```
        power          footprint         latency
       /     \          /      \         /      \
     low     high    compact   full  realtime  batch
   (저전력) (고성능) (경량화) (풀스케일) (실시간) (배치)
```

셀 = 각 축에서 수준을 하나씩 고른 조합. 2 × 2 × 2 = **8칸**. 전부 셀 수 있다.
MCMC가 “고차원 공간을 헤매며 가능 조합을 찾는다”는 문장은 이 크기에서는
과하다. 여기서 MCMC가 하는 일은 **금지 여부의 불확실성을 샘플로 남기는 것**이다.

```
전체 카르테시안 곱 (8)

  power=low | footprint=compact | latency=realtime     ...
  power=low | footprint=compact | latency=batch        ...
  power=low | footprint=full    | latency=realtime     ← 가설 금지 후보
  power=low | footprint=full    | latency=batch        ← 가설 금지 후보
  power=high| footprint=compact | latency=realtime     ← 가설 금지 후보
  ...
  power=high| footprint=full    | latency=batch

제약 C를 걸면 일부 칸이 공간 밖으로 나간다.

        8칸 전체                제약 후 S
     +--+--+--+--+            +--+--+--+--+
     |  |  |  |  |            |  |  |XX|XX|
     +--+--+--+--+     -->    +--+--+--+--+
     |  |  |  |  |            |XX|  |  |  |
     +--+--+--+--+            +--+--+--+--+
        점유 = 색             XX = 모순 (빈 칸이 정상)
                              빈칸 + S 안 = gap
```

## 1. 데이터 구조 — 가장 기본은 희소 카운트

글의 답: 행 = 특허, 열 = 키워드 빈도 (+ CPC 이진 + 피인용).

```
특허 i

  title + abstract
       |
       |  dictionary 문구를 센다 (대소문자 무시)
       v
  [ 2, 0, 0, 1, 0, 4, 0, ... ]     X_i   길이 = 문구 수 (수십)
         \_________________/
          대부분이 0  → 희소 벡터

  CPC  "G06N20/00;;H04W4/70;;..."
       |
       v
  [ G06N=1, G06F=0, H04W=1, Y02D=0, ... ]

  cited_by = 12                    숫자 하나
```

한 특허가 행렬에서 어떻게 보이는지:

```
display_key     n_hits  cpc_G06N  kw_low-power  kw_lightweight  kw_real-time ...
US 12,345 B2       5        1           2              3              0
US 9,876 A1        0        1           0              0              0   ← 사전에 안 걸림
```

**기대할 수 있는 것**

- 400건 중 상당수는 `n_hits = 0`. 사전이 Edge AI 전체를 덮지 않는다.
  이 행은 EM에서 **모든 셀에 균등 확률**로 남는다. 점유가 아니다.
- 키워드가 잡힌 행은 보통 1~3개 원천만 켜진다. “세 축을 다 채운 셀”은 드물다.
- CPC 플래그는 보조다. 이번 EM은 아직 X(키워드)만 쓴다.

**기대해선 안 되는 것**

- 이 벡터가 시나리오 공간 자체인 것. 공간은 8칸짜리 이산 격자다.
- 단어 임베딩 좌표. 없음.

`01_signatures.csv`의 비트열은 “어떤 문구가 켜졌는가”의 지문이다.
missing-species의 **종(species)** 으로 쓴다.

```
특허 A  0010100001...   지문 α
특허 B  0010100001...   지문 α   (같은 종, 빈도 +1)
특허 C  1000001000...   지문 β
...
한 번만 나온 지문 = f1 (singleton)
```

## 2. EM — 특허를 셀에 확률로 얹기

결측은 “이 특허의 셀 번호”다. 축을 새로 찾는 과정이 아니다.

```
관측     X_i  = 키워드 카운트
잠재     Z_i  ∈ {8개 셀}
파라미터  π_k = 셀 k 의 사전 비중
          θ_k = 셀 k 에서 문구가 나올 확률 (다항분포)

E-step   r_{ik} = P(Z_i = k | X_i, π, θ)
         = 정규화[  π_k  *  ∏_w  θ_{k,w}^{X_{i,w}}  ]

M-step   π_k  ← 평균_i r_{ik}
         θ_k  ← ( ∑_i r_{ik} X_i  +  smoothing ) / 합

반복     log-likelihood 가 거의 안 움직이면 멈춤
         기록은 02_em_loglik.csv  (감사)
```

그림으로 한 특허:

```
특허 i  키워드:  low-power×2, lightweight×1, (real-time 없음)

        셀                              r_ik   막대
low|compact|realtime                 ████░░░░  0.41
low|compact|batch                    ███░░░░░  0.33
low|full|realtime                    █░░░░░░░  0.08
low|full|batch                       █░░░░░░░  0.07
high|...                             ░░░░░░░░  나머지

hard map = argmax = low|compact|realtime
하지만 이 특허를 그 칸에 "있다"고 단정하지 않는다.
점유는  soft: occupancy_k += r_ik
```

초기값: 셀 `low|compact|realtime`의 θ는 그 세 수준 문구에 **미리 무게**를 둔다.
그래서 EM은 “8토픽 발견”이 아니라 **잠근 격자로의 소프트 매핑**이다.

```
반복이 하는 일

  t=0   사전 시드 θ
   |    저전력 문구가 많은 특허 → low 셀 쪽으로 r 이 기울어짐
   v
  E     r 갱신
   |    r 을 가중치로 그 셀의 문구 분포를 다시 셈
   v
  M     θ, π 갱신
   |
   +--> loglik 이 올라가야 한다. 내려가면 구현 오류.
```

**기대할 수 있는 것**

- `02_em_loglik.csv`의 loglik은 초반에 오르고 평평해진다.
- 키워드가 있는 특허의 `hard_prob`는 0.3~0.9. 1.0은 드물다 (문구가 한 칸만 가리킬 때).
- `entropy`가 높으면 그 특허는 여러 칸에 걸쳐 있다 = 글이 말한 “셀이 불확실”.
- 빈 문서(n_tokens=0)는 r = 1/8. **Coverage를 가짜로 올린다.** 리포트가 이 점을 적는다.
- 기대 점유 `expected_occupancy`는 정수가 아니다. 400 × 평균 r.

**기대해선 안 되는 것**

- 숨은 기술 테마를 새로 꺼내는 것. 테마(축)는 사전에 이미 있다.
- 하드 매핑이 정답인 것. 주결과는 r, 하드는 읽기 보조다.
- 빈 문서를 어떤 셀의 점유로 읽는 것.

## 3. MCMC 혼합 — 특허 = 기술 원천의 혼합체

유전학 admixture의 자리만 옮긴다.

```
유전학                         이 골격
개인                           특허
유전자 좌위                    키워드 토큰 (low-power 한 번, lightweight 한 번, ...)
조상 인구 K개                  원천 3개: power / footprint / latency
개인별 조상 비중 q             특허별 기술 비중 q
```

```
특허 i  토큰:  [low-power] [low-power] [lightweight] [real-time]

각 토큰의 숨은 기원 z

   low-power     -->  z = power        (사전 시드)
   low-power     -->  z = power
   lightweight   -->  z = footprint
   real-time     -->  z = latency

Gibbs 한 스텝: 토큰 하나를 집어 현재 z를 빼고
               다른 원천에서 나왔을 확률로 다시 뽑는다.

   P(z=k | 나머지) ∝  (그 특허의 k 토큰 수 + α)
                    * (원천 k 에서 그 문구 수 + β) / (원천 k 총토큰 + βV)

수천 스텝 후 평균내면

   q_i ≈  [ power=0.50, footprint=0.25, latency=0.25 ]
```

한 특허의 혼합 막대:

```
US xxx
  power      ████████░░░░  0.50     저전력 얘기가 절반
  footprint  ████░░░░░░░░  0.25     경량화는 조금
  latency    ████░░░░░░░░  0.25
```

`03_admixture_phi.csv`는 원천 k가 어떤 문구를 좋아하는지다.
시드가 사전 축과 같으므로, power 원천의 phi는 low/high 에너지 문구에 남아 있어야 한다.
Gibbs가 축 라벨을 서로 바꿔 버리면 (label switching) 막대가 뒤집힌다.
시드를 사전 축에 묶어서 그 위험을 줄였다.

**기대할 수 있는 것**

- 토큰이 있는 특허만 q가 의미가 있다. 0토큰 행의 q는 사전 α 때문에 거의 1/3.
- 한 축 문구만 있는 특허는 그 원천 q ≈ 1.
- `03_admixture_trace.csv`의 mean_q_* 는 burn-in 이후 흔들기만 하고 추세는 없어야 한다.
- 이것은 **셀 매핑이 아니다.** 셀은 수준 조합이고, q는 축 비중 분해다.
  “저전력 0.7 + 경량화 0.3”은 셀 이름 `low|compact|*`와 비슷하지만 latency 수준은 안 고른다.

**기대해선 안 되는 것**

- q로 8칸 점유를 대체하는 것.
- 키워드가 다른 축에서 “진짜로 왔다”는 인과.

## 4. MCMC 제약 — 금지인지 gap인지

글의 예: “극저전력인데 풀스케일/초고성능”. 우리는 그걸 **가설 쌍**으로만 넣는다.
관측이 0이라고 곧바로 금지가 아니다.

```
쌍 (power=low , footprint=full)

  400건 중
    low 문구가 있는 행     n_a
    full 문구가 있는 행    n_b
    둘 다 있는 행          n_both     ← 핵심

  모형   p = P(한 특허가 그 쌍을 동시에 보여 줌)
         p ~ Beta(1,1)  사전
         n_both | p ~ Binomial(n, p)
         사후 p ~ Beta(1+n_both, 1+n-n_both)

  그림 (사후)

        밀도
          |
        * |     n_both 가 크면 오른쪽
       *  |     n_both ≈ 0 이면 0 근처에 몰림
      *   |
     *    +------------ p
          0           0.01        ...
                |
                이 골격의 "금지 후보" 컷
                P(p < 0.01 | data)
```

가능 셀 샘플 한 장:

```
for draw = 1 .. 400
    각 가설 쌍에 대해 p ~ Beta(사후)
    p < 0.01 이면 그 쌍을 이번 드로우의 금지로 켠다
    켜진 금지를 어기는 칸은 지운다
    남은 칸에서 EM의 π (셀 비중)로 칸을 하나 뽑는다

결과 히스토그램 = "제약이 불확실할 때 칸이 얼마나 자주 살아남는가"
```

```
드로우 17:  금지 켜짐 = low×full
            남은 칸에서 샘플 → low|compact|realtime

드로우 18:  금지가 하나도 안 켜짐
            8칸 전부에서 샘플 → low|full|batch   (이번엔 허용)

드로우 19:  두 금지 모두 켜짐
            남은 칸이 더 줄어듦
```

8칸이라 기브스로 공간을 “탐색”할 필요는 없다. 매 드로우에서 **남은 칸을 정규화해 뽑으면** 된다.

**기대할 수 있는 것**

- `n_both`가 수십이면 `P(rate<0.01)`은 거의 0. 그 쌍은 금지로 안 죽는다.
- `n_both`가 0이어도 n이 400이면 p의 사후는 0 근처지만, “관측 실패”와 “불가능”을
  아직 가르지 못한다. 그래서 컷 0.01은 **시연용**이다. 물리 법칙이 아니다.
- MCMC 샘플 빈도는 EM 점유와 비슷하되, 금지 후보 칸만 조금 깎인다.
- 금지 칸의 샘플 비중이 0이 아니면, 데이터가 그 금지를 자주 안 켠다는 뜻이다.

**기대해선 안 되는 것**

- 샘플 하나가 “미래 시나리오”. 샘플은 가능 공간의 **측도**다.
- 빈 칸 = 기회. 빈 칸은 (모순 | gap | 사전이 못 잡음) 중 하나다.

## 5. 품질 지표가 여기서 하는 일

글: MCMC 샘플의 경험적 분포로 Coverage / Diversity를 잰다.

이 골격은 **같은 8칸**에 대해 세 소스를 나란히 둔다.

```
소스 A  EM hard argmax          가장 거친 점유
소스 B  EM expected occupancy   소프트 점유 (주결과)
소스 C  MCMC 가능-셀 샘플       제약이 들어간 점유
```

정의 (이번 파일의 조작적 정의):

```
occupancy 가중치 w_k  (합이 1이 되게 정규화 → p_k)

Coverage   =  질량이 거의 있는 칸 수 / 8
              "거의" = p_k > 1/(8*20)
              빈 문서의 균등 r 이 이 숫자를 올린다.

Balance    =  H(p) / log(8)
              1 = 여덟 칸에 고르게,  0 = 한 칸에 몰림

Diversity  =  ∑_{k,ℓ} p_k p_ℓ Hamming(cell_k, cell_ℓ)
              0 ~ 3.  두 번 뽑았을 때 축이 몇 개나 다른지
```

```
Balance 낮음              Balance 높음
  ████████                  ██  ██  ██  ██
  칸 하나에 몰림            여러 칸에 퍼짐

Diversity 낮음            Diversity 높음
  이웃 칸만 차 있음         축이 서로 다른 칸들이 같이 참
  (low|compact|* 만)       (low 와 high 가 둘 다 있음)
```

**기대할 수 있는 것**

- B(EM expected)의 coverage ≥ A(hard). 소프트가 질량을 더 여러 칸에 뿌린다.
- C(MCMC)의 coverage ≤ B. 금지가 켜지면 칸이 줄어든다. 안 켜지면 A/B와 비슷.
- 키워드가 한쪽으로만 잡히면 Balance가 낮다. 실패가 아니라 사전의 치우침일 수 있다.
- Diversity가 0에 가까우면 사실상 한 종류의 조합만 본 것.

**기대해선 안 되는 것**

- Coverage 높음 = 좋은 시나리오 공간. 빈 문서 균등 할당만으로도 올라간다.
- 이 숫자가 RQ2의 최종 정의. 프로토콜 문서가 아직 없고, 이 폴더는 시연이다.

## 6. Missing-species — “아직 안 본 조합이 얼마나 더 있나”

글의 Fisher–Robbins / 미발견 종. **닫힌 8칸에는 쓸 일이 거의 없다.**
최대가 8이고, 종 수가 칸 수를 넘을 수 없다.

그래서 종을 **키워드 존재 지문**으로 둔다 (열린 공간).

```
관측된 지문 종류   S_obs
한 번만 나온 지문  f1
두 번 나온 지문    f2
문서 수            N   (키워드가 1개라도 있는 행)

Chao1     S_obs + f1² / (2 f2)     (f2=0 이면 보정 공식)
Good-Turing P_new ≈ f1 / N         다음 특허가 새 지문일 확률
```

```
지문 빈도
  ████████  f1  많음  → 아직 못 본 키워드 조합이 더 있다
  ██        f2
  █         f3+

Chao1 - S_obs  =  "숨은 지문 수"의 하한에 가까운 추정
```

**기대할 수 있는 것**

- 문구가 수십 개면 지문 공간이 2^V로 거대하고, S_obs ≪ 2^V, f1이 크다.
  Chao1이 S_obs보다 꽤 클 수 있다 = 사전이 잡아도 조합은 아직 안 다 봤다.
- P_new가 높으면, 400건은 키워드 조합을 덮기에 작다.

**기대해선 안 되는 것**

- Chao1 = 미개척 시나리오 셀 수. 셀은 8개로 닫혀 있다.
- Chao1 = 블루오션 개수.
