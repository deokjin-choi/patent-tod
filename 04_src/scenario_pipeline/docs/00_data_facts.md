### 표준화 수준의 트리플 밀도

| 단위 | 공간 크기 | 관측 unique | 밀도 |
|---|---:|---:|---:|

v1 4관계 수준은 밀도 17.2%로 너무 촘촘해서 "미관측=negative" 가정이 위험하다. **50 STD 관계 수준이 학습·negative 생성의 합리적 지점이다.**

### 관계 버킷의 의미 오염 (negative sampling 설계에 직결)

| 항목 | 값 |
|---|---|
| `confidence_score` | 최소 0.438 / 중위 0.547 / 최대 0.821, **50개 중 37개가 0.6 미만** |
| 버킷 크기 | 최소 9 / 중위 43 / 최대 170 |
| v1 관계로의 배분 | `Achieves_Effect` 23버킷, `Implemented_By` 15, `Addresses_Problem` 10, `Comprises_Component` 2 |

구체적 충돌 사례:

| 관계 | STD 버킷 | v1 매핑 |
|---|---|---|
| `requires` | STD_REL_8 | Achieves_Effect |
| `prevents` | **STD_REL_8 (동일)** | Achieves_Effect |
| `improves` | STD_REL_10 | Achieves_Effect |
| `increases` | **STD_REL_10 (동일)** | Achieves_Effect |
| `reduces` | STD_REL_24 | Achieves_Effect |
| `comprises` | STD_REL_33 | Comprises_Component |

원안의 예시 negative(`requires` → `reduces`)는 버킷이 8 vs 24로 갈리므로 살아남는다. 그러나 **`requires`와 `prevents`가 같은 버킷**이라, STD 버킷 수준에서 관계를 교체하면 "논리적으로 반대인 관계"가 같은 라벨을 받는다.
→ 관계 교체 negative는 **표면 관계(2,634종) 수준에서 생성**하고, 같은 STD 버킷 내 교체는 negative로 인정하지 않는다.
