# 알려진 판정 이슈

표본 검증과 전체 집계에서 확인한 내용을 남긴다. 프롬프트 버전을 고칠 때 여기부터 본다.

## v4: F1 과대 매핑 (매핑 단계 순서 편향)

- **증상.** F1(수확 대상 식별)이 실제로는 식별이 아닌 동작에 `direct`로 붙는다. 전체 수확 장치 320건에서 F1이 `direct`인 296건 중 288건(97%)이 카드 기능 id `1`을 포함했다. 표본 40건에서 F1 일치율은 20%(범위 안 수확 장치만 보면 27%)로, F2–F4보다 훨씬 낮다.
- **원인.** 카드 단계가 아니라 **매핑 단계**다. 카드는 F1–F4와 무관하게 동작을 `1, 2, 3…`으로만 적는다. 매핑이 F1부터 채우면서, 내용과 상관없이 **카드 1번**을 F1에 연결하는 순서 편향이 생겼다. 카드 1번은 흔히 모터 구동·프레임·이송 시작처럼 식별이 아닌 동작이다.
- **카드는.** 같은 표본·파일럿에서 카드 요약 자체는 대체로 쓸 만했다. 문제는 “카드 기능 → F1–F4” 대응이다.
- **영향.** 분업 방식에 F1이 들어간 조합(F1–F4, F1·F3 등) 건수가 부풀려진다. F3·구분·범위 판정은 상대적으로 덜 흔들린다.
- **대응.** 프롬프트 **v5**에서 매핑만 고쳤다. (1) 카드 id 순서는 F1–F4와 무관하다고 명시, (2) 특허마다 F1–F4 채움 순서를 무작위로 넣어 프롬프트를 다시 조립(고정 순서로 앞선 기능이 과대 매핑되는 것을 피함; 순서는 출력의 `fill_order`에 기록), (3) F1은 작물 위치·상태를 읽는 신호 동작에만 연결하고, 없으면 `not_mentioned`가 정상이라고 적음, (4) 기능공간 예에 올리브 떨이(구동=1번이어도 F1 아님)를 넣음. 카드 프롬프트는 v4와 같다. 기존 v4 카드로 v5 매핑을 다시 돌리려면 `--card-version v4`를 쓴다.
- **증거.** `llm_output/validate_v4_mistral__mistral/score.md`, 수확 장치 F1→id1 연결 97%. v4 전체 집계·공백 검토 기록: `05_data/agri/fv_harvest/llm_output/v4_mistral__mistral_full_review.md`.

## 그 밖에 열린 이슈

- **장치 형태.** 표본 40건 일치 60%(진짜 수확 장치 22건에서는 77%). 소농형/대규모형 규모는 형태+동력으로 계산하므로 형태 오류에 끌린다.
- **범위.** 품종 특허, 수확 후 분리, 시료 채취, 전정망 등이 범위 안으로 들어온 경우가 있다(표본 범위 일치 78%).
- **구분(수확 장치/부품).** F3를 수확 후 선별·이물 제거에 잘못 붙이면 부품이 수확 장치로 집계된다.
- **매핑 뒤 청구항 경계 강제.** 파일럿에서 강제하면 점수가 떨어져 채택하지 않았다.
