# 과일·채소 수확 특허의 기능 매핑

확장초록(`01_paper/2026-winter/extended-abstract.md`) 4.1–4.2절의 형태로 특허를 판정하는 작업 폴더다. 특허마다 하위 기능 F1–F4(수확 대상 식별, 수확 위치 조정, 작물 분리·채취, 수확물 수집·이송)와의 관계를 본문 근거와 함께 기록한다.

Python은 `conda run -n scenario-space python ...`으로 실행한다.

## 단계

| 순서 | 파일 | 하는 일 | 산출 |
|---|---|---|---|
| 1 | `10_select_scope.py` | CPC로 과일·채소 수확 특허를 고른다 | `05_data/agri/fv_harvest/scope.csv` |
| 2 | `20_fetch_fulltext.py` | Google Patents에서 본문을 한 건씩 받는다 | `fulltext/{공개번호}.json`, `fetch_log.csv` |
| 3 | `30_build_llm_input.py` | 본문에 위치 표시를 붙여 카드 단계 입력을 만든다(호출 없이 확인용) | `llm_input/{공개번호}.json`, `.user.txt` |
| 4 | `40_run_card_pass.py` | 본문을 읽혀 과제와 무관한 카드를 받는다 | `llm_output/card_v2/{모델}/{공개번호}.json` |
| 5 | `50_run_card_mapping.py` | 카드만 읽혀 F1–F4에 대응시킨다 | `llm_output/mapping_fv_harvest_v2/{카드모델}__{모델}/` |
| 6 | `60_check_output.py` | 인용 대조, 카드 구조 점검, 수확 장치·부품 기술·분업 방식 계산 | `llm_output/check_v2_*.csv` |

보조 스크립트: `21_repair_encoding.py`(초기 수집의 인코딩 오류 복구, 한 번 실행함), `22_reparse_fulltext.py`(파서를 고친 뒤 저장한 HTML로 본문 JSON을 다시 만듦), `35_pick_pilot.py`(CPC 하위 그룹마다 한 건씩 파일럿 8건 선정).

산출은 모두 `05_data/agri/fv_harvest/` 아래에 두며, Git에는 올리지 않는다.

## 1. 범위

원본은 `05_data/agri/Planting_harvesting_storage_US.csv`(20,564건)이다. CPC 또는 IPCR 기호가 아래 그룹에 하나라도 걸리면 범위에 넣는다. 정의는 `config.py`의 `SCOPE_GROUPS`에 있다.

| 그룹 | CPC | 건수 |
|---|---|---:|
| `picking` | A01D46 과일·채소 따기, 나무·관목 털기. 목화(46/08–46/18)는 제외 | 671 |
| `standing_vegetable` | A01D45 가운데 파인애플, 토마토, 아스파라거스, 오이, 콩, 완두, 양배추·상추, 시금치, 작업자 운반 | 139 |
| `root_crop` | A01D13–33 뿌리작물 캐기. 땅콩(A01D29)은 제외 | 255 |
| `ground_gathering` | A01D51/002 사과·견과 줍기, A01D51/005 비트·감자 적재 | 58 |
| 합계(중복 제외) | | 1,044 |

79건은 두 그룹 이상에 걸친다. `scope.csv`의 `scope_groups` 열에 걸린 그룹을 모두 적었다.

## 2. 본문 받기

- Lens 번호를 Google Patents 공개번호로 바꾼다. `US 2024/0415055 A1`은 `US20240415055A1`, `US 11234567 B2`는 `US11234567B2`가 된다.
- 요청은 한 번에 하나만 보내고, 요청 사이 간격은 1초 이상이다(`REQUEST_INTERVAL_SEC`).
- HTTP 429나 5xx가 오면 30초, 60초, 120초, 240초를 기다렸다가 다시 시도한다.
- 이미 받은 파일은 건너뛴다. 중간에 멈춰도 다시 실행하면 이어서 받는다.
- 전체 1,044건은 약 20–30분 걸린다.

저장하는 항목은 서지(제목, 우선일, 출원일, 공개일, 출원인), 초록, 청구항(번호, 본문, 종속항 여부, 인용한 청구항), 본문(소제목과 문단 번호가 붙은 문단)이다.

## 3. LLM 입력

LLM 호출은 두 번으로 나눈다(프롬프트 v2).

| 단계 | 입력 | 출력 | 언제 |
|---|---|---|---|
| 카드 단계 | 특허 제목과 본문 | 카드(card). 과제와 무관하다 | 특허마다 한 번 |
| 매핑 단계 | 저장한 카드 | 과제 대응(mapping) | 기능공간이 바뀌거나 다른 과제로 넓힐 때마다 |

카드 단계에는 기능공간을 보여주지 않는다. v1에서는 한 번에 둘을 받았더니 작은 모델이 F1–F4 틀에 맞춰 카드를 지어냈다.

파일은 `prompts/v2/`에 있고, `prompt_build.py`가 조립한다.

| 파일 | 내용 |
|---|---|
| `card_pass.md` | 카드 단계 시스템 프롬프트 |
| `card_mapping.md` | 매핑 단계 시스템 프롬프트 |
| `function_space_fv_harvest.md` | 과일·채소 수확 기능공간(F0, F1–F4, 판정 예). 매핑 프롬프트의 `{{FUNCTION_SPACE}}` 자리에 들어간다 |
| `labels_v2.json` | 모든 선택지의 정의. 프롬프트의 `{{OPTIONS}}` 자리에 들어간다 |
| `card_v2.schema.json` | 카드 형식 |
| `mapping_fv_harvest_v2.schema.json` | 과일·채소 수확 대응 형식 |

Ollama는 출력 스키마를 형식 강제에만 쓰고 프롬프트에 넣어주지 않는다. 그래서 선택지와 정의를 `labels_v2.json`에서 읽어 프롬프트에 붙인다. 스키마의 선택지와 정의 파일이 어긋나면 `prompt_build.py`가 멈춘다. v1은 이 목록을 보여주지 않아서 모델이 동사와 분류를 모른 채 골랐다.

카드에 담는 항목:

- 발명 대상(장치, 방법 등과 짧은 명사구), 발명이 달리는 기계(`host_machine`)
- 기능 최대 8개. 발명이 하는 일뿐 아니라 사용자나 발명이 달리는 기계가 하는 일도 적고, 누가 하는지(`actor`)를 붙인다. 동사는 Hirtz 등(2002) 기능 기반에서 고른다
- 구성요소, 문제, 효과(짧은 문장과 유형)
- 대상 작물, 형태, 동력원, 운용 환경, 필요한 기반시설, 붙는 대상. 소농 조건으로 걸러낼 때 쓴다

수행 주체(`actor`)는 동력원으로 판정한다. 사람 힘으로 쓰는 손 도구는 `human`이다.

매핑에는 범위 분류(`scope.category`), F1–F4 각각의 연결된 카드 기능(`card_functions`), 관계(`direct`, `support`, `not_mentioned`), 수행 주체, F3의 분리 원리를 담는다. 범위는 식용 과일·채소 수확만이다. 목화·사탕무 같은 공업용 작물, 솎기·전정·잔재 처리, 수확 뒤 더미 적재·선별은 범위 밖이다.

수확 장치와 부품 기술의 구분, 분업 방식은 LLM에게 묻지 않고 `60_check_output.py`가 규칙으로 계산한다. F3가 `direct`이면 수확 장치다. 분업 방식은 수행 주체가 기계(발명 또는 발명이 달리는 기계)인 기능의 조합이다.

입력은 제목과 본문(description)만 쓰고 초록·청구항은 넣지 않는다. 본문이 상한을 넘으면 배경기술 절은 앞 3,000자만 남기고(발명이 풀려는 문제가 대개 여기 있다), 그래도 넘으면 뒤를 자른다. 근거 인용에는 본문 문단 위치(`[P0023]`)를 붙인다. 예전 PSE 추출(`04_src/em_mcmc/docs/pse_slot_review.md`)은 자유 서술이라 칸마다 문장이 거의 다 달라 셀 수가 없었다. 그래서 보기에서 고르게 하고, 자유 서술은 짧은 구로 제한했다.

## 로컬 모델 실행 조건 (RTX 4060 8GB)

모델이 전부 GPU에 올라가는 최대 문맥 길이다. 넘으면 일부가 CPU로 가서 크게 느려진다.

| 모델 | 문맥(`--num-ctx`) | 비고 |
|---|---:|---|
| `mistral` (7B) | 10240 | |
| `llama3` (8B) | 8192 | 모델의 최대 문맥 |
| `qwen3:8b` | 7168 | 생각 모드 지원(`--think on/off`) |
| `gemma` (1세대 7B) | 없음 | 문맥 4096에서도 일부가 CPU로 간다 |
