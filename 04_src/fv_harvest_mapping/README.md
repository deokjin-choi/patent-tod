# 과일·채소 수확 특허의 기능 매핑

확장초록(`01_paper/2026-winter/extended-abstract.md`) 4.1–4.2절의 형태로 특허를 판정하는 작업 폴더다. 특허마다 하위 기능 F1–F4(수확 대상 식별, 수확 위치 조정, 작물 분리·채취, 수확물 수집·이송)와의 관계를 본문 근거와 함께 기록한다.

**전체 흐름(카드→매핑→파생·집계)만 보려면:** [`pipeline_ko.md`](pipeline_ko.md)  
**선택지 한글 목록:** [`prompts/v5/labels_v5_ko.md`](prompts/v5/labels_v5_ko.md)

Python은 `conda run -n scenario-space python ...`으로 실행한다.

## 단계

| 순서 | 파일 | 하는 일 | 산출 |
|---|---|---|---|
| 1 | `10_select_scope.py` | CPC로 과일·채소 수확 특허를 고른다 | `05_data/agri/fv_harvest/scope.csv` |
| 2 | `20_fetch_fulltext.py` | Google Patents에서 본문을 한 건씩 받는다 | `fulltext/{공개번호}.json`, `fetch_log.csv` |
| 3 | `30_build_llm_input.py` | 본문에 위치 표시를 붙여 카드 단계 입력을 만든다(호출 없이 확인용) | `llm_input/{공개번호}.json`, `.user.txt` |
| 4 | `40_run_card_pass.py` | 독립 청구항과 본문을 읽혀 과제와 무관한 카드를 받는다 | `llm_output/card_v5/{모델}/{공개번호}.json` |
| 5 | `50_run_card_mapping.py` | 카드의 청구항 표시를 코드로 바로잡고(`claim_check.py`), 카드만 읽혀 F1–F4에 대응시킨다 | `llm_output/mapping_fv_harvest_v5/{카드모델}__{모델}/` |
| 6 | `60_check_output.py` | 인용 대조, 카드 구조 점검, 수확 장치·부품 기술·분업 방식 계산 | `llm_output/check_v5_*.csv` |
| 7 | `65_score_pilot.py` | 파일럿 8건을 정답(`pilot_gold.json`)과 대조해 확장초록 4.2절 모양의 표로 낸다 | `llm_output/score_{버전}_{실행}.md` |
| 8 | `70_aggregate.py` | F1–F4 관계 비율, 분업 방식, 작물군·분리 원리·장치 형태·CPC 그룹별 교차표 | `llm_output/aggregate_{버전}_{실행}/patents.csv`, `tables.md` |
| 9 | `80_gap.py` | 분업 방식별 패턴과 소농 노동과의 연결 점검, 저개발 칸·사다리 공백·규모 공백 탐색(`01_paper/2026-winter/method.md` 5절) | `llm_output/gap_{버전}_{실행}/gap.md`, `cells.csv`, `devices.csv` |

8–9단계의 작물군은 LLM이 붙인 분류가 아니라 카드의 대상 이름을 `crop_groups.py` 사전으로 묶은 값이다. 이름이 'fruit'처럼 일반어면 본문에서 작물 이름을 세어 한 작물군이 3번 이상이고 60% 이상일 때 그 작물군으로 둔다. 동력원이 사람 힘뿐인 장치는 LLM이 수행 주체를 발명으로 적었더라도 사람으로 고친다.

프롬프트 버전은 `config.py`의 `PROMPT_VERSION`(기본 v5)이다. 예전 버전은 `PROMPT_VERSION=v4 conda run -n scenario-space python ...`처럼 환경 변수로 고른다. v5는 매핑만 고쳤으므로, 이미 만든 v4 카드로 다시 매핑할 때는 `--card-version v4`를 붙인다.

보조 스크립트: `21_repair_encoding.py`(초기 수집의 인코딩 오류 복구, 한 번 실행함), `22_reparse_fulltext.py`(파서를 고친 뒤 저장한 HTML로 본문 JSON을 다시 만듦), `35_pick_pilot.py`(CPC 하위 그룹마다 한 건씩 파일럿 8건 선정).

산출은 모두 `05_data/agri/fv_harvest/` 아래에 두며, Git에는 올리지 않는다.

## 1. 범위

원본은 `05_data/agri/Planting_harvesting_storage_US.csv`(20,564건)이다. CPC 또는 IPCR 기호가 아래 그룹에 하나라도 걸리면 범위에 넣는다. 정의는 `config.py`의 `SCOPE_GROUPS`에 있다.

| 그룹 | CPC | 건수 |
|---|---|---:|
| `picking` | A01D46 과일·채소 따기, 나무·관목 털기. 목화(46/08–46/18)는 제외 | 671 |
| `standing_vegetable` | A01D45 가운데 파인애플, 토마토, 아스파라거스, 오이, 콩, 완두, 양배추·상추, 시금치, 작업자 운반 | 139 |

| 합계(중복 제외) | | 1,044 |

79건은 두 그룹 이상에 걸친다. `scope.csv`의 `scope_groups` 열에 걸린 그룹을 모두 적었다.

## 2. 본문 받기

- Lens 번호를 Google Patents 공개번호로 바꾼다. `US 2024/0415055 A1`은 `US20240415055A1`, `US 11234567 B2`는 `US11234567B2`가 된다.
- 요청은 한 번에 하나만 보내고, 요청 사이 간격은 1초 이상이다(`REQUEST_INTERVAL_SEC`).
- HTTP 429나 5xx가 오면 30초, 60초, 120초, 240초를 기다렸다가 다시 시도한다.
- 이미 받은 파일은 건너뛴다. 중간에 멈춰도 다시 실행하면 이어서 받는다.
- 전체 1,044건은 약 20–30분 걸린다.

저장하는 항목은 서지(제목, 우선일, 출원일, 공개일, 출원인), 초록, 청구항(번호, 본문, 종속항 여부, 인용한 청구항), 본문(소제목과 문단 번호가 붙은 문단)이다.

## 3. LLM 입력

LLM 호출은 두 번으로 나눈다(프롬프트 v5).

| 단계 | 입력 | 출력 | 언제 |
|---|---|---|---|
| 카드 단계 | 특허 제목, 독립 청구항, 본문 | 카드(card). 과제와 무관하다 | 특허마다 한 번 |
| 매핑 단계 | 저장한 카드 | 과제 대응(mapping) | 기능공간이 바뀌거나 다른 과제로 넓힐 때마다 |

카드 단계에는 기능공간을 보여주지 않는다. v1에서는 한 번에 둘을 받았더니 작은 모델이 F1–F4 틀에 맞춰 카드를 지어냈다.

파일은 `prompts/v5/`에 있고, `prompt_build.py`가 조립한다. v5 카드 프롬프트는 v4와 같다. 달라진 것은 매핑 프롬프트다. 특허마다 F1–F4 채움 순서를 무작위로 넣고, F1은 감지·식별 동작에만 연결하라고 적는다. 알려진 이슈는 [`known_issues.md`](known_issues.md)에 적는다.

| 파일 | 내용 |
|---|---|
| `card_pass.md` | 카드 단계 시스템 프롬프트 |
| `card_mapping.md` | 매핑 단계 시스템 프롬프트 |
| `function_space_fv_harvest.md` | 과일·채소 수확 기능공간(F0, F1–F4, 판정 예). 매핑 프롬프트의 `{{FUNCTION_SPACE}}` 자리에 들어간다 |
| `labels_v5.json` | 모든 선택지의 정의. 프롬프트의 `{{OPTIONS}}` 자리에 들어간다 |
| `labels_v5_ko.md` | 위 선택지의 한글 분류·의미 (참고용) |
| `card_v5.schema.json` | 카드 형식 |
| `mapping_fv_harvest_v5.schema.json` | 과일·채소 수확 대응 형식 |

Ollama는 출력 스키마를 형식 강제에만 쓰고 프롬프트에 넣어주지 않는다. 그래서 선택지와 정의를 `labels_v4.json`에서 읽어 프롬프트에 붙인다. 스키마의 선택지와 정의 파일이 어긋나면 `prompt_build.py`가 멈춘다. v1은 이 목록을 보여주지 않아서 모델이 동사와 분류를 모른 채 골랐다.

카드에 담는 항목:

- 발명 대상(장치, 방법 등과 짧은 명사구), 발명이 달리는 기계(`host_machine`)
- 기능 최대 8개. 발명이 하는 일뿐 아니라 사용자나 발명이 달리는 기계가 하는 일도 적고, 누가 하는지(`actor`)를 붙인다. 동사는 Hirtz 등(2002) 기능 기반에서 고른다
- 구성요소, 문제, 효과(짧은 문장과 유형)
- 대상 작물, 형태, 동력원, 운용 환경, 필요한 기반시설, 붙는 대상. 소농 조건으로 걸러낼 때 쓴다

수행 주체(`actor`)는 동력원으로 판정한다. 사람 힘으로 쓰는 손 도구는 `human`이다.

매핑에는 범위 분류(`scope.category`), F1–F4 각각의 연결된 카드 기능(`card_functions`), 관계(`direct`, `support`, `not_mentioned`), 수행 주체, F3의 분리 원리를 담는다. 범위는 식용 과일·채소 수확만이다. 목화·사탕무 같은 공업용 작물, 솎기·전정·잔재 처리, 수확 뒤 더미 적재·선별은 범위 밖이다.

수확 장치와 부품 기술의 구분, 분업 방식은 LLM에게 묻지 않고 `60_check_output.py`가 규칙으로 계산한다. 범위 판정과는 따로 계산한다. F3가 `direct`이면 수확 장치다. 분업 방식은 발명이 직접 수행하거나 지원하는 기능 가운데 수행 주체가 기계(발명 또는 발명이 달리는 기계)인 기능의 조합이다.

v3부터 독립 청구항을 본문 앞에 붙인다(`[C1]`). 청구항은 발명이 어디까지인지를, 본문은 그 부품이 무엇을 왜 하는지를 알려 준다. 카드의 기능과 구성요소마다 그것을 적은 독립 청구항(`claim`)을 붙이고, 매핑에서는 청구항에 있는 부품의 동작만 `direct`로 본다. 본문에만 나오는 발명이 달리는 기계나 선택 부품의 동작은 `not_mentioned`다. 종속 청구항은 넣지 않는다. 취소된 청구항은 뺀다.

v4부터는 모델이 붙인 청구항 표시를 매핑 전에 `claim_check.py`가 바로잡는다. 모델은 본문에만 나오는 부품에도 청구항 번호를 붙이기 때문이다. 부품 이름의 내용어 가운데 절반 이상이 한 독립 청구항 문장에 있으면 그 청구항으로, 아니면 `none`으로 고친다. "system", "unit" 같은 말은 내용어로 치지 않는다. 바로잡은 내역은 매핑 출력의 `claim_fixes`에, 실제로 넘긴 카드는 `card_used`에 남는다.

카드 입력은 청구항과 본문을 합쳐 13,000자, 출력 상한은 2,560토큰이다. Mistral 문맥 10,240토큰 안에 둘이 함께 들어가도록 맞춘 값이다.

입력은 제목, 독립 청구항, 본문(description)이고 초록은 넣지 않는다. 본문이 상한을 넘으면 배경기술 절은 앞 3,000자만 남기고(발명이 풀려는 문제가 대개 여기 있다), 그래도 넘으면 뒤를 자른다. 근거 인용에는 본문 문단 위치(`[P0023]`)를 붙인다. 예전 PSE 추출(`04_src/em_mcmc/docs/pse_slot_review.md`)은 자유 서술이라 칸마다 문장이 거의 다 달라 셀 수가 없었다. 그래서 보기에서 고르게 하고, 자유 서술은 짧은 구로 제한했다.

## 로컬 모델 실행 조건 (RTX 4060 8GB)

모델이 전부 GPU에 올라가는 최대 문맥 길이다. 넘으면 일부가 CPU로 가서 크게 느려진다.

| 모델 | 문맥(`--num-ctx`) | 비고 |
|---|---:|---|
| `mistral` (7B) | 10240 | |
| `llama3` (8B) | 8192 | 모델의 최대 문맥 |
| `qwen3:8b` | 7168 | 생각 모드 지원(`--think on/off`) |
| `gemma` (1세대 7B) | 없음 | 문맥 4096에서도 일부가 CPU로 간다 |

## 아직 하지 않은 것

- v5 매핑을 파일럿·표본(또는 전체)에 다시 돌려 F1 과대 매핑이 줄었는지 확인하기. 카드는 v4를 재사용(`--card-version v4`).
- 매핑 뒤에도 청구항 경계를 코드로 강제할지 정하기. 파일럿에서는 카드가 부품 이름을 청구항과 다르게 적은 경우(로봇의 "칼날" 대 청구항의 "용기")가 있어, 강제하면 오히려 틀린 칸이 늘었다.
- 장치 형태·범위(품종·수확 후 처리) 오판 줄이기. 자세한 내용은 [`known_issues.md`](known_issues.md).
- 파일럿 정답(`pilot_gold.json`)을 연구자가 확인하기.
